Where to get data and how to fill inputs

Choose your input before filling the form

Use the values required by the particular test case. The suite uses a mixture of fixed samples, newly generated text, existing accounts and uploaded files. A name shown in another example is not automatically the right value for your case.

The HTML bundle includes file descriptions and readable data/source references. It does not contain the binary upload samples, working account credentials, or a running application. The test-project paths tell the automation maintainer which files or setup to provide.

Record the values you used

A useful test note records the product and website, case name, account condition, input value or file name, expected result, and actual result. For example: “Website QR; URL example.com; internal QR name QA Website Check 01; expected the saved URL to remain unchanged after reopening.” The QR name in this example is an illustrative manual choice, not a fixed value used by the suite.

For a failure from an automated run, obtain the captured input or prepared-data record from that run. Asking the generator to make another name or date can give a different value and a different result.

Optional automation detail follows. A dataset is a file of test values. A default is a helper's fallback sample value. A fixture file is a prepared upload sample. These terms describe where values come from; they are not fields to enter in the application.

Optional automation detail: trace a value to its source

Example: pdfQrCreate() calls setPdfCompanyName(this.fakeCompany()). The input method receives a string, types it, and asserts preview text. The company value comes from Faker, not the DB, .env, account profile or PDF file. Conversely, setPdfWebsite() without arguments uses its own fixed google.com default.

spec argument / dataset row
  → recipe argument or explicit setter argument
  → if omitted, method default applies
  → locator fill / typing / upload / selection
  → preview or persistence assertion

For any field, find the test in spec map, inspect its imports/local variables, find the called method in code index, and check its signature plus field writes. Use the exact assertion's expected value, not an unrelated similarly named dataset.

Uploads: manual and automated

Manual use: obtain the actual sample file from the automation maintainer, select it through the browser, and check the preview or error specified by the case. The table gives the exact project paths to request.

Automation detail: run from repository root because default asset paths are relative. Upload methods either call setInputFiles(path) on a native input or wait for a filechooser event before clicking the upload zone and then setFiles(path). The event promise must be created before the click.

The asset library also contains large files, unsupported-format samples, malformed/corrupt images, transparent/very wide/very tall images, protected PDF, silent videos, MP3s with/without covers, and an SVG payload. Use the complete asset list; a filename like 30mb.jpg is not an authoritative measured size. Generated upload security fixtures may be built in code rather than stored as files; trace uploadSecurityPayloads.data.ts and its consumers.

Manual reproduction: select the same file through the browser, use the same preceding help-dialog and accordion actions, then compare the same upload/preview/error result. Native FileList can be cleared after frontend upload; Event uses preview/delete controls to prove success. Upload success does not prove the public scan image persists after save.

Phone, URL, date and number pitfalls

  • WhatsApp: fillWhatsappPhoneForSubmit() chooses Israel then types its default national number. setWhatsappPhoneNumber() only fills the number. If the widget auto-selects another country, the same number may fail validation.
  • URLs: BASE_URL identifies the app under test; example.com/google.com are QR content. Scan origin, app origin, admin origin and Stripe origin are separate.
  • Dates: yearly/quarterly/monthly expiry helpers use 365/90/30 day offsets, not calendar-year/quarter/month arithmetic. getExpiryDateOneYearAhead() returns MM/YY; subscription helpers return SQL-like datetime strings.
  • Event dates: helpers select calendar buttons and confirm; readonly inputs cannot be treated as ordinary text fields. Default tomorrow uses the host clock.
  • Numbers: phone, ZIP, card number and coupon code are strings; preserve leading zeroes. Monetary unit conversion must follow the specific Stripe/pricing helper and currency rules.
  • Typing: fill() replaces; pressSequentially() appends unless the helper first clears. Match the test's event behavior when reproducing a bug.

Shared matrices are selections, not universal coverage

global-constants.ts supplies qrTypes, allPlans, and flows=['DPF','CFF']. It does not include NSF in that flow array. Edit, download, analytics and Step 3 constants are separate matrices. Adding a type to one does not add it everywhere. Before editing a shared row, use the generated data consumer list to see which suites will expand.

Event scenario catalogues, acceptance criteria and field master JSON are distinct: a documented scenario is not automatically an executable test. Status gates, loops, feature availability and project filters still decide what runs. Spec reference exposes the test declarations and skip/fail/fixme calls.

Additional matrices and run filters

These concrete matrices help when selecting a manual example:

  • constants/download-tests.ts defines PNG, JPEG, SVG and EPS with default/512/1024/2048/4096 selections. PNG/JPEG rows include expected pixel size; vector rows do not assert a pixel size through that field. Follow the consuming spec for file-content checks.
  • pricing-integrity/official-stripe-prices.data.ts maps plan IDs 1=monthly, 2=annual monthly-equivalent, 3=quarterly monthly-equivalent, 4=discounted, 5=one-time, 6=14-day full-access total, 7=14-day limited-access total. It reads official stripe prices.csv, with annual/quarterly monthly equivalents falling back to total divided by 12/3 and rounded to two decimals. This is this parser's mapping, not a universal rule for every Stripe price ID or currency.
  • Visual helpers accept comma-separated VISUAL_LANG and VISUAL_VIEWPORT to filter configured language/viewport rows. Use IDs from screens.config.ts/the visual helper, not arbitrary display labels. constants/step3-tests.ts also contains hardcoded OQG dev onboarding URLs, so those cases can navigate away from a differently configured project URL.

Optional automation detail: change one case without changing shared defaults

const title = 'QA image validation title'
await pageManager.step2Page.setImageTitle(title)
await pageManager.step2Page.setImageWebsite('example.com')
await pageManager.step2Page.uploadImage(
    'tests/data/test_files/image_files/sample-blue.webp'
)

This only changes the chosen call. Editing setImageTitle()'s default changes every caller that omits its argument. Editing a shared locator affects all consumers. Put new feature datasets under tests/data/<feature>.data.ts and reusable setup under tests/helpers/<feature>.helper.ts, following repository standards.
