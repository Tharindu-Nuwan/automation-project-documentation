Automation setup and execution

Start · Next: accounts

Optional technical detail. This page is for people setting up or running automated tests. For a manual product check, use Your first check. The commands below belong in a configured development environment; they are not steps to type into the product.

Follow one test from the command line

package.json script / Playwright CLI
  → playwright.config.ts loads env.ts and defines projects
  → selected project supplies baseURL + product + browser settings
  → fixtures/baseFixture.ts supplies pageManager, apiManager, env, adminAuth
  → spec beforeEach sets up its user and starting page
  → test calls a Page Object or API helper
  → Page Object uses locators and shared BasePage helpers
  → assertions inspect UI, API, database, email, or downloaded files
  → spec afterEach performs its declared cleanup
  → reporter records the result and configured artifacts

The browser page and API request are Playwright fixtures. The custom fixture constructs managers; it does not automatically register a user, log in, buy a plan, delete a user, or read mail. Those operations happen only when a spec/helper requests them. There is no configured shared storageState login in the root config.

Product, environment, and browser are separate choices

Product is oqg, qci, qga, or qgc. Environment is the deployment URL. Browser is Chromium, Firefox, Edge configuration, or WebKit. oqg-chromium does not itself mean staging: OQG_BASE_URL decides where it goes.

The main config has 16 product/browser projects, a deprecated chromium project, four folder-counter browser projects, and three password-changed browser projects. An unfiltered npm test selects all configured projects. Choose a project and a feature deliberately.

ModelURL and product selectionMain trap
Product projectsOQG_BASE_URL, QCI_BASE_URL, QGA_BASE_URL, QGC_BASE_URL; typed product fixtureProject existence is not full feature implementation
Legacy chromiumRoot BASE_URL, fixture product defaults to oqg; some selectors use DOMAIN or infer from BASE_URLSetting DOMAIN=qci does not change the typed product fixture
utils/productEnv.tsProduct URL first, legacy BASE_URL fallback; adds scheme if missing, resolves originDifferent behavior from raw ${BASE_URL}path concatenation

env.ts loads root .env through dotenv. Existing shell variables take precedence under the default dotenv behavior. defineEnv() trims values, then merges shared into each product with product fields winning. OQG/QCI/QGA base URLs are required when the module is imported, even before CLI project filtering. QGC has a hardcoded dev fallback. Missing optional values fail later when a feature actually needs them. An empty string is not undefined: ?? fallbacks do not replace empty values.

Actual factory support

Login, Register, Account, EmailBodyOQG, QCI

Other pages are concrete shared classes, sometimes with product arguments or legacy domain logic. A shared class is not proof its DOM works on every product. PageFactory returns a proxy for unsupported products and calls test.skip() on member access. A skipped QGA login test is not a passed QGA login test. QGC main-config projects match only the two landing visual specs.

Browser nuance: oqg-edge explicitly sets channel: 'msedge'; QCI/QGA/QGC Edge projects use the Desktop Edge device preset without that explicit channel. Safari-named projects run Playwright WebKit. Dedicated Google Chrome / Microsoft Edge projects explicitly request branded channels. See config.

Set up and run a focused example

Use the repository root and the team's Node version compatible with installed dependencies. package.json does not pin a Node engine; workflows use lts/*.

npm ci
npx playwright install chromium

Create local .env from the team's approved configuration; .example.env is a starting point, not proof that every current lookup is present. At minimum, config evaluation needs real test-target values for OQG_BASE_URL, QCI_BASE_URL, and QGA_BASE_URL. Add the variables required by the selected feature from Chapter 2. Never use placeholder hosts for a real run.

# Discover cases without executing browser actions.
QASE_MODE=off npx playwright test tests/logged-out-user/login/login.spec.ts --project=oqg-chromium --list

# Use configured existing login credentials.
QASE_MODE=off npx playwright test tests/logged-out-user/login/login.spec.ts --project=oqg-chromium --workers=1 --retries=0 --headed

# Inspect a specific case interactively.
QASE_MODE=off npx playwright test tests/logged-in-user/create-qr-code/website-qr.spec.ts --project=oqg-chromium --grep 'Fill only the required fields' --debug

Some legacy login assertions concatenate ${baseURL}qr-codes; their expected URL needs a trailing slash and the correct locale path. Newer relative navigation /register resolves at the origin and discards a base URL locale path. Check both the navigation and assertion in the selected spec before changing URL configuration.

npm run test:dev changes ignores through npm_lifecycle_event; it does not select a dev URL. Its Event exclusions are active, but the email exclusion is commented out. tests/tools is globally ignored; deprecated chromium overrides testIgnore with [], so an unrestricted legacy run can include persistent-data generators. Verify collection with --list before running that project broadly.

Separate visual config: npm run test:visual -- --project=oqg-chromium-visual matches only create/generate landing specs. Baselines use test-results/visuals/{arg}{ext}; visual run output goes to test-results/visual-runs. Percy is a different path. See visual config.
