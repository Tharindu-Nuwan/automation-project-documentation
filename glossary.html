Words used in this guide

Plain-language meanings for the product and automation terms you may encounter.

You do not need to memorise these terms. Return here when a reference page uses an unfamiliar word. Start a practical task with Your first check.

Terms and meanings

Product
The application being checked. This suite uses OQG, QCI, QGA, and QGC as product identifiers. Features implemented in the tests differ between them.
Environment / deployment
A particular running copy of the product, reached by a website address. Confirm the exact address for your check. A product name or browser choice does not select the environment by itself.
Credentials
The sign-in details for an account, usually an email and password. Obtain the actual values through the team’s approved access process.
Existing account / fresh account
An existing account has already been registered and may contain data or a subscription. A fresh account is newly registered for a check. Inventing an email address does not create an account.
Guest / logged out
A browser session that is not signed in. Guest flows can behave differently from signed-in flows.
Test case / scenario
A starting situation, a sequence of actions, and a result to check. A scenario may test a normal action or an intentionally invalid input.
Test data / input
Values or files used for a check: names, addresses, dates, account details, upload files, or prepared product records.
Required / optional field
A required field must be completed for the relevant action to succeed. An optional field can be left empty in that case. The exact requirements depend on the QR type and test.
Validation / boundary check
Validation is how the form accepts or rejects an input. A boundary check uses an exact limit, or a value just beyond it, such as text length or file size.
Expected result / actual result
Expected is what the case says should happen. Actual is what you observed. Record the difference precisely when they do not match.
Preview / save / scan
Preview shows how content may look during creation. Saving creates or updates a stored QR. Scanning opens the result reached from the QR. A successful preview does not establish that saving or scanning works.
Internal QR name
The name used to identify a QR in the account. It is different from the destination URL or the content visible after scanning.
QR password / account password
A QR password can restrict access to scanned content. An account password signs you in. They are separate inputs.
Default / override
A default is a value an automation helper uses when no replacement is supplied. An override is the replacement passed by a particular test. The test’s override takes priority.
Generated value / Faker
A value made by code for a run, often a name, email, or paragraph. Faker is a library used for this. Generated values can change between runs and may not have an exact requested length.
Automation / Playwright
Automation is code performing actions and checking results. Playwright is the tool this repository uses to drive browsers and run tests.
Spec / test declaration
A spec is a file containing automated test cases and their setup. A declaration is a test definition in the code; loops and browser choices can make that definition run more than once.
Helper / method / Page Object
A helper or method is a reusable action or sequence. A Page Object groups actions for a screen. A method with Create in its name may only fill a form; its exact behavior is described in the reference.
Locator / selector
The rule automation uses to find an on-screen field, button, or other element. It is not a value to enter into the form.
Fixture
In automation setup, a fixture provides tools or prepared context to a test. An upload fixture is a prepared file. Neither term by itself means a user has already been registered or signed in.
Setup / hook / cleanup
Setup establishes the starting state. A hook is code that runs before or after selected tests. Cleanup removes or resets specified test data afterward; it varies by test.
API / database (DB)
An API lets code communicate with a service directly. A database stores records. Some tests read or change these records without clicking the product interface; those technical details are optional for manual testing.
Environment variable / .env
A named configuration setting and a local file that can supply settings to automation. For example, DEFAULT_USER_LOGIN is the setting name, not the actual login address.
Mailpit / Mailtrap
Mailpit is the test email service used by the current mail helper. The repository still has a Mailtrap-named compatibility helper; its name alone does not identify a separate working inbox.
Stripe / subscription / plan
Stripe is used for payment integration. A plan describes an offering; a subscription is an account’s recurring billing arrangement. Billing checks need the case’s prepared account and payment setup.
Assertion / pass / fail / skipped
An assertion is an automated comparison with an expected result. Pass means the executed checks succeeded. Fail means a check or required action failed. Skipped means the test was not executed; it is not a pass.
Retry / timeout / polling
A retry repeats a failed action or test. A timeout limits how long it may wait. Polling repeatedly checks whether an expected change has appeared.
CI / report / artifact
CI is an automated job that can run the suite. A report lists run results. Artifacts are evidence such as screenshots, videos, or downloaded files; which ones exist depends on the run settings.
Source snapshot / line link
A readable copy of code bundled with this guide. A line link opens a particular line in that copy. It is documentation, not a running test or proof that the current product behaves that way.
