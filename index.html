Before you start a check

  1. Confirm the product and exact test website address. A product name alone does not identify the test environment.
  2. Confirm whether to stay logged out, use an existing account, or create a new one. Ask your QA lead or the person maintaining the tests for approved access.
  3. Find the values and files required by your assigned case. Some cases need an account with an existing plan, payment, QR, or scan history.
  4. Know the expected stopping point: form validation, preview, saved QR, or scanned result. These are different checks.
  5. Agree which records to keep or delete when finished. Preserve shared accounts and evidence needed for a bug report.

Use this guide offline

Extract the complete qa-kt.zip, open its qa-kt folder, and double-click index.html. Keep the other files and folders together. Page links, search, and printing work without installing software or starting a server. Use the search box to find a topic; use your browser’s Find command to locate a word inside a page.

This bundle contains the documentation and readable copies of relevant code. It does not contain working account credentials or the actual upload files. Upload reference pages show the original filename, repository location, and measured size; ask your QA lead or test maintainer for the corresponding file. An internet connection and approved access are still needed to test the product itself.
